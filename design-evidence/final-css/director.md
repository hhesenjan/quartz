## Evidence behind the decisions

**Paper.** I independently exported A4 Home and the Azure article on Letter with background graphics from each frozen preview. The first print candidate recovered the long command layout and gave prose dark ink on white. Its Home footer fit on page one while page two was empty. Its printed Azure article still showed the interactive Contents strip and painted red code glyphs in RGB 215,58,73 on RGB 241,239,230. Both later builds printed one Home sheet, hid that strip, and painted the same red token in RGB 156,47,57, giving about 6.3:1 contrast on the code panel. The two later page-four independent PDF rasters were byte-identical. Reviewers also recovered the full text of all twenty populated macOS description cells and all seven distinct long Azure source lines. The severity differences in cycle 49 do not affect the decision. Small technical text at 3.97:1 warranted correction. [Print samples](director/proof.jpg) · [Browser print readings](director/paper.json) · [Visual, accessibility and CSS print assessments](reviews.md#cycle-49)

**Forced colors and keyboard.** In a fresh Chrome context on every preview I opened Search, entered `#az`, selected `#azure` with Down, examined the field and accepted it with Enter. Through cycle 50 the field displayed only “ure,” even though the input still held the prefix. The final build paints every character, preserves the caret boundary and returns focus to the Search button on Escape. The surrounding outlines and Close control keep their system colors. The correction is local to the decorative completion layer. [Independent input crops for all four previews](director/inputs.png) · [Keyboard readings](director/search.json)

**Explorer and surrounding screens.** I inspected the paired Home, listing, article, code, search, graph and drawer captures across phone, tablet and desktop in both themes. The matched article illustration and caption preserved their geometry. The archive hierarchy, page measure, full-opacity dark and light text, and 14.5px TX-02 examples remained legible. I exercised the final phone drawer on Blog, Azure and Certifications in both branded browsers. Direct-coordinate taps on scrolled Blog and Azure held 500px before opening, while scrolling the tree and after closing on the published-equivalent and final previews. Escape restored focus. My first locator-based tap scrolled the opener into view before dispatching the tap. The direct-touch replay isolates the site's actual behavior. The complete final Chrome and Brave route sweeps each passed 320 out of 320 mobile states, covering both themes on every one of the 160 routes with Explorer. The dedicated 404 has no drawer. Chrome's settled drawer was pixel-identical after hiding the content beneath it in every state. Eight direct-coordinate checks on the public Blog and Azure routes also passed at an underlying scroll position of 520px. [Light screens](director/frames-light.jpg) · [Dark screens](director/frames-dark.jpg) · [Chrome touch checks](director/coordinates-chrome.json) · [Brave touch checks](director/coordinates-brave.json) · [Public-site checks](validation.json)

**Home refresh.** On Chrome and Brave I panned the certification table before reloading Home normally and twice in quick succession at 390, 900 and 1440px. All six combinations recovered the exact previous horizontal offset. Each wide view retained one local canvas, the global graph opened and Escape restored focus, and reduced motion removed local canvases. Phones omitted the graph. The broader branded exercise also covered midpoint and end positions, rapid reloads at two intervals and repeated render events. [Chrome](director/chrome.json) · [Brave](director/brave.json)

**Acceptance and limits.** The production build emitted 913 files and all 167 unit tests passed. SCSS formatting and whitespace checks passed. The 252 HTML routes preserved text, IDs and link targets, and the shipped JavaScript and WOFF2 files matched the baseline. The final 2,576 layout states covered 161 pages. The 44 axe states reported zero automated violations; some contrast readings required manual examination. Both saved themes passed the representative A4 and Letter review, including backgrounds-enabled code. The separate repository-wide type check still reports the same pre-existing `micromorph` and `remark-parse/lib` declaration errors. Both workflows that run it are gated to the upstream repository. This fork's Pages build and the design gate's test suite passed. Browser evidence comes from Linux, emulated touch and forced colors, native Firefox zoom, and PDF output. Physical handset and printer behavior remains unverified.
